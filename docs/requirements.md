# CooCowork 需求分析

Owner: `src/definition.ts`(本页写的需求由它声明的工具与事件兑现)

调研原文见 [research.md](research.md)。那份由调研子代理从网页汇总,2026 年的条目(Meta Muse、OpenAI Dots、Gemini Daily Brief 等)晚于本会话模型的知识截止,没有逐条复核,引用时看它标的来源。

## 定位

CooCowork 让 Coo 在使用者干活时坐在旁边:知道对方在不在电脑前、前台在用什么、接下来有什么日程,该开口时开口;每天的工作痕迹按天留在本机,第二天 Coo 能接上前一天的事。

参照对象各取一点:

| 产品 | 借鉴 | 避开 |
|---|---|---|
| Dot | 跨天连续:记得对方在忙什么、说过要做什么 | 主动消息多到成负担(内测加上后又砍掉);追问像面试 |
| Meta Muse | 主动程度可调;只在有新事实时通知;动作前要确认 | 给屏幕上出现的第三方建档;「忘记」不删原始数据 |
| ChatGPT Pulse / Gemini Daily Brief | 一天一次、有结尾的简报 | 每晚后台研究(成本高,Coo 没有这个场景) |
| Windows Recall / Screenpipe | 本机存储、按程序排除、无痕窗口不记 | 定期全屏截图 |
| body doubling(陪伴式专注) | 说好目标和时长,有人在旁边陪着 | 监工式的指责 |

## Coo 现在有什么

| 能力 | 现状 | 位置 |
|---|---|---|
| 长期记忆 | 工作区文件,`PARTNER.md` 全文进前缀,每次写入一个 git 提交 | `Coopanion/core/persona.ts` |
| 定时叫醒自己 | `alarm_set`,daily 可重复,错过的下次启动补送 | `Coopanion/core/alarms.ts` |
| 看屏幕、操作电脑 | 电脑操作工具,默认关;开着时按需截图 | `desktop-pet/src/cua/` |
| 无事件时主动说话 | Cormini 心跳,Coopanion 默认关(`tick.intervalMinutes: null`) | `cormini/persona/heartbeat.ts` |
| 知道对方在不在、在用什么 | 没有 | |
| 读对方的日历 | 没有 | |
| 陪着专注 | 没有 | |

所以 Coo 现在只在被戳、被叫、自己设的唤醒器到点时醒来。它不知道对方什么时候坐下、什么时候走开、几点开会。

扩展市场里已有的相关第三方包:`cortico-world-presence`(窗口列表、在场、摘要、截图)、`cortico-world-break`(固定间隔的久坐喝水提醒)、`cortico-world-agenda`(bot 自己的日程表与便签)、`cortico-world-notes`。CooCowork 不依赖它们(扩展市场的 TAGS.md 强烈不建议 World 之间互相依赖),也不重复它们的定位:presence 是通用的窗口观察器,break 是固定间隔计时,agenda 是 bot 给自己排的日程;CooCowork 读使用者自己的日历,把在场、专注、日程合在一个「陪着干活」的场景里。

## 需求

| 编号 | 需求 | 依据 |
|---|---|---|
| R1 | 在场:离开、回来、每天第一次坐下、连续在电脑前满一段。只报键鼠与前台窗口能确认的事实 | Cortico「诚实的认知论」;Dot/Muse 的主动都需要触发点 |
| R2 | 前台程序与窗口标题按天记录,可按天回顾 | Dot 的 living history;Pulse/Brief 的前一天概要 |
| R3 | 读使用者已有的日历(.ics 文件或订阅地址),日程前提醒,日程中不打扰 | Poke/Gemini 的会议提醒;Recall 只读不写 |
| R4 | 专注时段:目标、时长、要避开的程序或网站;停在避开项上提醒一次,结束时给统计 | body doubling |
| R5 | 主动程度两档 + 安静时段;叫醒 Coo 的事件少而有据 | Muse 的档位;Dot 主动消息过多被砍 |
| R6 | 隐私:数据只在本机;无痕窗口和聊天程序不记标题;一句话删除某天或全部记录;不截图 | Recall 重做后的做法;Muse 的第三方档案与「忘记」争议 |
| R7 | 跨天连续:每天第一次坐下时带上前一天概要和今天日程,Coo 结合自己的笔记接上 | Dot |
| R8 | 一天叫醒 Coo 的次数可估、可压 | 桌宠按次计费;Dot 的打扰教训 |

## 不做

- **定期截屏或读屏幕内容**:成本高、隐私风险大;要看屏幕时 Coo 用已有的电脑操作工具按需截图。
- **在 World 里存待办或记忆**:Cortico 规定 World 不写 Memory。对方的进度、打算由 Coo 记在自己的工作区。
- **写日历、发消息、建会议**:只读。
- **设置窗口普通模式里的界面**:Coopanion 规定扩展不在普通模式开界面入口。配置在高级模式的 World 页。
- **判断「在不在工作」「是不是在摸鱼」**:World 只报事实,专注时段的避开项由对方自己说。
- **macOS / Linux**:前台窗口与空闲时长只实现了 Windows;别的系统上事件只剩日历和专注时段。

## 使用场景与验收

每条都在 `tests/e2e.test.ts` 的模拟工作日里跑过,见 [e2e-transcript.md](e2e-transcript.md)。

1. 早上 9 点第一次坐下:Coo 被叫醒,收到「上次活动 10-18 23:40」、前一天 2 小时 40 分钟的概要和今天两项日程。
2. 9:20 收到「10 分钟后站会」,只此一次;重启后不重复(`tests/world.test.ts`)。
3. 使用者打字「我要写周报,一个小时,别让我刷b站」:Coo 调 `cowork_focus_start`,避开项 `bilibili`。
4. 10:20 切到 B 站,停满 2 分钟后 Coo 被叫醒一次;10:30 连续坐满 90 分钟,因为在专注时段里只随下一批送达。
5. 10:49 专注时段结束:在电脑前 60 分钟,避开项上 6 分钟,前台 Word 54 分钟。
6. 12:00 离开吃午饭:「离开」不叫醒;13:10 回来时叫醒,同一批里带着 12:00 那条离开。
7. 14:00–15:00 评审会上连续坐满不叫醒,正文写明日历上此刻是哪个日程。
8. 17:44「今天我都干了啥」:`cowork_day` 给出程序与标题的分钟数;「以后每天六点提醒我复盘」:Coo 用已有的 `alarm_set`;「把今天的记录删掉」:`cowork_forget` 删掉当天文件。

这一天 World 叫醒 Coo 9 次(另有使用者打字 4 次)。
